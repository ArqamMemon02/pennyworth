## 2026-10-05 — Milestone 1: display stack + simulator
- **Graphics choice: LVGL 9.6 with its built-in SDL simulator.** Picked over LovyanGFX because LVGL ships an official SDL desktop backend (`lv_sdl_window_create`) out of the box — the simulator deliverable needs no custom wrapper — and the widget/timer/animation system LVGL already has is exactly what Milestones 2-5 need (day/night transitions, state-machine-driven sprites, a launcher). LovyanGFX is lighter and has great GC9A01 support, but has no desktop simulator story, so hitting "round mask + clock text in the simulator" would've meant writing that bridge by hand first. Heavier dependency, but it's the lazier path to everything the roadmap actually asks for.
- Config: copied LVGL's `lv_conf_template.h` into `include/lv_conf.h` (enabled via `LV_CONF_INCLUDE_SIMPLE`), flipped it on, enabled Montserrat 28 for the clock face, and made `LV_USE_SDL` conditional on a `PENNYWORTH_SIMULATOR` build flag so the ESP32 build doesn't need SDL headers.
- Hardware-agnostic UI code lives in `lib/pennyworth_ui/` — a single `pennyworth_ui_init()` that draws the round mask (visualizes the physical display's circular visible area) and a live clock label. Called identically from both entry points.
- Two entry points, selected per-env via `build_src_filter`: `src/main_native.cpp` (SDL window + mouse input, `lv_timer_handler()` loop) and `src/main_esp32.cpp` (Arduino `setup()`/`loop()`, LVGL display buffer in RAM, flush callback is a stub). The ESP32 side has no real panel driver yet — the board hasn't arrived and CLAUDE.md says never guess pins — so `flush_cb` just acks the buffer. Milestone 6 replaces that stub with a real GC9A01 driver once pins are verified into `include/board_pins.h`.
- Gotcha: PlatformIO's "native" platform build doesn't put the project's `include/` dir on the search path when compiling library sources (only the final app TU), so LVGL's own `lv_conf.h` lookup failed until `-Iinclude` was added explicitly to both envs' `build_flags`.
- Verified: `pio run -e native -t exec` opens an SDL window showing the round mask with a live `HH:MM:SS` clock (confirmed via screenshot). `pio run -e esp32-s3` builds clean too — 34.6% RAM, 16.5% flash.

## 2026-10-05 — Milestone 2: the world
- `lib/pennyworth_world/` — hardware-agnostic again, drawn as children of the round mask. `pennyworth_world_update()` is called from the existing 1s clock timer, no new timer needed.
- **Tone:** 9 keyframes across 24h (deep night → warm amber morning → bright day → warm evening → dim cool night → wrap), linearly interpolated per-channel on the fractional hour. Kept all keyframe colors mid-saturation on purpose — a near-white "bright day" or near-black "deep night" would wash out the white clock text, so brightness stays bounded even at the extremes.
- **Moon phase:** Conway's algorithm (`lib/pennyworth_world/moon_phase.cpp`) — a closed-form date formula, no lookup tables, per CLAUDE.md. Unit-tested in `test/test_moon_phase/` against 4 known new moons and 4 known full moons (2000-2024), via `pio test -e native`. Accurate to ~1 day in practice (verified by prototyping the formula in Python against the same reference dates before writing the C++).
- **Moon rendering:** two overlapping same-size discs (light "lit" + dark "shadow"), shadow offset horizontally by `(1-cos(2π·phase))/2 · diameter`, sign flipping at the half-cycle mark so waxing and waning mirror each other through the quarters. No image assets, no canvas — just two circle widgets.
- **Sun/stars/moon visibility** is a hard cut at the day/night boundary (6:30/18:00); only the background tone transitions continuously. Stars are 14 fixed-but-seeded dots, each with its own randomized infinite ping-pong opacity animation for twinkle.
- **Two real bugs found by actually screenshotting the simulator, not just checking it built:**
  1. `lv_obj_set_style_clip_corner()` on the round mask hid *everything* — including the dead-centered clock label — not just the square corners it was meant to crop. Root cause not chased down (LVGL 9.6 + SDL software renderer, possibly a known issue); the fix instead was to drop clipping entirely and size/position every element (moon's max shadow excursion included) with enough margin to stay geometrically inside the 120px-radius circle by construction. Cheaper on the ESP32 besides — no per-frame clip mask.
  2. Day/night visibility only updated *on change* (`is_day != s_is_day`), and `s_is_day`'s default (`true`) happened to match a boot during daytime, so the toggle silently never ran and night-only elements stayed visible under a blue sky. Fixed with an explicit `s_visibility_applied` latch so the very first `pennyworth_world_update()` call always sets visibility regardless of what the static default happens to be — a lesson for the state machine in Milestone 3 too: initialize explicitly, don't rely on a comparison against a guessed default.
- Verified both day and night visually (screenshots, including a temporary forced-hour build to exercise the day path) before committing. `pio run -e esp32-s3` still builds clean — 34.6% RAM, 16.8% flash.
